# WageGo 与 Fundo 对比代码同步检查

检查日期：2026-11-11。已更新 [WageGo 画像](html/wagego_profile_report_slides.html)、[Fundo/WageGo 对比](html/compare_profile_report_slides.html)，并同步重建 [Fundo 画像](html/fundo_profile_report_slides.html)。

## 需要同步的问题

| 检查项 | 原问题 | 调整后 |
|---|---|---|
| 收入与收支口径 | WageGo 及对比仍沿用旧解释，没有加载标签收入/支出核验字段 | 两组共用金额恒等式核验；现金流体系和标签体系分别解释 |
| 新增维度 | 对比加载器没有读取 Fundo 上次新增的变量 | 两组均加载相同的 16 个扩展字段；单独报告与对比复用同一计算模块 |
| 工资与账单负担 | 相对工资的比率被直接称为“真实可支配收入” | 改为工资负担或收入来源代理；不重复加总存在交集的支出类目 |
| 赌博 P99 | WageGo 仍把六个月累计金额分位数称为“单笔 P99” | 修正累计借记标签；同时纳入同类贷记形成净流出指标 |
| 催收统计 | `collections_inc` 是催收类支出覆盖，被标为“催收类拒付” | 图表与卡片改为催收类支出；真正的催收拒付字段仍单独保留 |
| 分层拒付占比 | 实际计算有拒付记录的用户占比，注释却写成按笔数计算 | 表头及注释明确用户占比，与代码中的分层聚合一致 |
| 用户分层解释 | 含新增借款的盈余分层被用来判断信用质量“略好” | 明确融资流入影响净流量分层，不直接当作信用等级 |
| 可比性 | 两组月份构成不同，旧文字还预设“独立样本” | 增加共同月份检查及用户键重合检查；不预设统计独立性 |
| 维护方式 | 各报告容易分别修改、口径逐渐分叉 | 提取 `profile_enrichment.py`；对比模块加载同样字段，并支持一次加载同步生成三份报告 |

WageGo 文件有 13,422 个字段，原报告加载 171 个，本次加载 187 个；Fundo 有 13,363 个字段，加载 188 个。两者加载数相差 1，是样本月份元数据来源不同；新增 16 个业务字段及其公式、阈值完全对齐。未附独立变量释义字典，沿用字段名解释并补充数值核验。

## 新增结果是否值得展示

| 指标 | Fundo 全期 | WageGo 全期 | WageGo 共同月份 2026-09 |
|---|---:|---:|---:|
| 有效用户 | 21,057 | 35,851 | 19,579 |
| 还款/(工资+福利)中位 | 16.9% | 33.3% | 32.9% |
| 上述负担比有效人数 | 19,232 | 34,050 | 18,644 |
| ≥5 家已识别还款机构覆盖 | 22.9% | 47.2% | 48.2% |
| 未解决拒付用户占比 | 32.7% | 57.7% | 59.2% |
| 历史曾有负余额 | 70.0% | 84.9% | 85.5% |
| 赌博正净流出/工资福利 >5% | 14.4% | 19.3% | 19.9% |

Fundo 全部样本均在 2026-09，因此其共同月份结果与全期相同。WageGo 有效用户月份构成为：2026-08 为 440 人、2026-09 为 19,579 人、2026-10 为 15,832 人。共同月份检查后，上表主要差异仍存在，不能全部归因于月份构成；该检查也不等于已控制收入、借贷金额等其他差异。

两组有效样本的原始 `user_id` 键重合为 0；身份命名空间尚未核实，键值不重合也不作为统计独立性的证明。对比保留全期结果，另列共同月份结果，没有用共同月份悄悄替换原有样本。

近期双重压力（收入日均下降 >20% 且还款日均上升 >20%）在 WageGo 中识别出 2,324 人。该组同期未解决拒付率 63.2%，其余可比用户为 64.2%，两者接近，因此只把它作为近期资金变化信息，不称为明显更高风险。

## 输出与重建

- WageGo 从 17 页扩展为 24 页，对比报告从 21 页扩展为 27 页；Fundo 保持 24 页。三份报告共 75 页、46 张图表。
- [WageGo 完整变量审查表](data/wagego_variable_audit.csv)、[WageGo 扩展指标](data/wagego_enrichment_metrics.json)、[WageGo 交叉分析](data/wagego_cross_analysis.csv)。审查表记录完整字段清单；只给实际加载字段提供统计值。
- [全期与共同月份统计](data/fundo_wagego_cohort_comparison.csv)、[月份和用户键检查](data/fundo_wagego_comparison_checks.json)。每项指标都保留自己的有效人数，不能用总体人数替代工资福利比等条件指标的分母。
- `compare_profile_report.py` 负责加载和图表；`compare_profile_enrichment.py` 负责共同月份、用户键检查和新增比较；`profile_enrichment.py` 是两个品牌共用的业务计算；`wagego_profile_report.py` 保留原始基础指标计算，并支持额外字段加载。

推荐重建命令：

```powershell
python build_compare_decks.py --pair fundo_wagego --sync-profiles
```

该命令从原始 CSV 各加载一次，使用同一批数据和同一次生成时间，写出两份单独画像、对比报告及聚合审计数据。仍可单独运行 `python build_profile_decks.py --only wagego` 或 `python build_compare_decks.py --pair fundo_wagego`。

验证包括 9 项测试，覆盖分母缺失/非正值、净额、互斥窗口、共同月份限制、品牌共享计算、额外字段读取及导出命名隔离；另检查三份报告全部页面的渲染、溢出、脚本错误与图表尺寸。逐页结果在 `output/qa/*_sync_layout_results.json`，带 HTML 的 SHA-256 以核对检查对象。

新增 CSV/JSON 审计文件仅含聚合统计，不输出用户键或逐户财务数据；描述性差异不直接作为审批规则或因果结论。
